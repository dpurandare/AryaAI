# Changelog

All notable changes to this project are documented in this file. The format
follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this
project adheres to [Semantic Versioning](https://semver.org/) — see the
Versioning section in `README.md` for what that means while the major
version is still `0`.

## [Unreleased]

### Added

- The workspace's Python environment is now created automatically together with the workspace folders (`code/`, `documents/`, `resources/`, and `venv/`) when Python 3.10+ is installed, with pinned base packages for charts and Word/Excel files (matplotlib, numpy, pillow, python-docx, openpyxl). Settings > Runtime shows its state and offers Retry, Repair and Turn Python off. Existing environments are adopted, never overwritten.

- First run now includes a Python setup step: Continue is available once the environment is ready, or you can choose "Continue without Python". README documents Python 3.10+ as a prerequisite, and the Linux `.deb` now depends on `python3` and `python3-venv`.

- A new `describe_capabilities` tool lets the assistant list, from live data, which specialists and tools it has, which databases / APIs / email accounts / MCP servers are configured, whether Python scripts can be run, and which actions ask for confirmation — so "what can you do?" is answered from facts, not memory.
- Settings > Prompt caching: a switch (on by default) to stop sending Anthropic prompt-cache markers, as a recovery path should the API ever reject them.
- The planning step now asks the provider to constrain its reply to the plan's JSON shape (OpenAI-style `response_format`, Gemini `responseJsonSchema`, Anthropic a forced tool call; roles limited to the valid ones) instead of only asking for JSON in the prompt. A provider or model that rejects it is retried as a plain prompt and remembered for the session. `scripts/plan-probe.mts` measures the difference per model.
- When a local model ends a round with nothing at all (no text, no tool call — typically right after a tool result), the app now asks it to continue, up to twice, instead of ending the turn with a warning and the work undone. The planning step also accepts a reply that wraps its JSON in prose or a code fence, and the terminal message now shows what the model actually said.
- Math written with single dollar signs (`$613,898,527\text{ kWh}$`), which several models use, is now rendered as formatted math instead of showing raw LaTeX. Prices such as "$5 to $10" and dollar signs in code are left alone.
- The account row's arrow now toggles Settings open and closed (it turns over while Settings is open).
- Picking a session (or New chat) while Settings is open now switches to it. If something typed into Settings has not been saved — an API key, an "add …" form, an edited MCP description, the workspace folder — a prompt offers **Save and stay here**, **Discard and leave** or **Cancel**; settings that apply immediately (theme, toggles, selects) never need it.
- Ctrl + `+` / `-` / `0` (Cmd on macOS) zoom the whole app in, out and back to 100%, and the level is remembered between launches.
- The Settings page now scrolls across the whole panel (scrollbar at the window's right edge) with its content in a centred column of up to 900px that shrinks with the window, instead of a fixed 640px column pinned to the left.
- An expanded tool block now shows the tool's full command wrapped over several lines (multi-line scripts and SQL keep their line breaks) instead of a single ellipsised line.
- A permanent prompt-size test records the fixed per-request token cost and fails if it grows unnoticed.

- The evaluation scripts now work within free-tier limits (call spacing, a tokens-per-minute budget from actual usage, waiting out 429s, stopping with a partial result and a resume point when a request can never fit or a daily quota is exhausted).
- Google Gemini requests now report how much of the prompt was served from Gemini's automatic cache. Developer scripts `scripts/routing-eval.mts` and `scripts/cache-probe.mts` can follow through exploration rounds, try alternative router cores and run with a key taken from Sachivji's own secret store (`scripts/with-app-key.cjs`, key decrypted in memory and redacted from output).
- **Your own specialist roles.** Put a Markdown file (a small frontmatter block plus the role's prompt) in the roles folder — Settings > Roles > Open roles folder, or Create example file — and it appears in the Agent picker, can receive work from the assistant and can be a step in plans, with your next message and no restart. A role only chooses among existing tools, so confirmation and the workspace boundary still apply to everything it does. Settings > Roles lists them with the tokens each adds to every request, shows problems and quality warnings for each file, lets you switch them off, and keeps the last working version if an edit breaks a file. A role cannot reuse a built-in name.
- **Prompt caching for Anthropic models**: the tool list, system prompt and conversation prefix are marked cacheable, so multi-round tasks re-use what they already sent instead of paying for it every round (the context meter keeps counting cached tokens; Anthropic cost figures are now an upper bound). The tool descriptions for creating Word/PowerPoint documents and extracting templates are shorter (about 350 tokens less per request on the default router), and a per-tool size budget test guards against growth. `scripts/cache-probe.mts` measures caching on any provider with your own key.
- **MCP servers are now used through a dedicated MCP Operator specialist**, and only by it — a server with many tools no longer inflates every other request, and a coding or database task can no longer reach a wiki's write tools by accident. You can write a one-line description of each server in Settings > MCP servers (the assistant uses that, not the server's own text, to pick a server). A server's own tool descriptions are capped and labelled as untrusted third-party text.
- **Experimental slim router** (Settings > Slim router, off by default): the assistant's fixed per-request size drops from about 10,800 to about 2,800 tokens by keeping a few everyday tools directly and reaching the rest through specialists; earlier turns' calls to tools it no longer carries are replayed as text. Early testing on one local model shows it delegates data and history requests reliably but file, code and document requests less so — leave it off unless you are testing. `scripts/routing-eval.mts` lets you evaluate routing and history-replay compatibility with your own provider keys. Real tool usage is now counted locally.
- New `python_run` tool: the Developer runs Python by passing the source (or a `.py` path) directly — no shell quoting — in the workspace's virtual environment, and gets back the exit code, output, and the list of files the run really created (found by the app). You approve every run and see the code first. Charts and Word documents built with matplotlib and python-docx work end to end.
- **Specialists now hand each other real results.** The full result of a data-producing call (SQL rows, parsed files, API responses) is saved to a workspace file and given to the next specialist as an input, so it works from the actual data instead of a summary; the files a specialist really created or changed are detected by the app and listed as verified; a specialist can say it needs information from you (the plan pauses and you are asked) or that a request belongs to another specialist (redirected once). A tool that belongs to a specialist now answers "call delegate_to_<role>" instead of "Unknown tool".
- Each message can optionally show which model answered it, off by default.
- Tool output gained a third "Hidden" state alongside shown/collapsed: a tool's text is hidden, but an image or chart it produced is always shown, since that's usually the point of the result. Saving a session as Markdown or PDF now respects Hidden too.
- **The Windows installer now bundles a standalone Python interpreter with the same pinned packages described above, and a CPU-only Ollama runtime for local search history** — neither needs to be installed separately on Windows. The `nomic-embed-text` embedding model itself is pulled once over the network on first run (keeps the installer smaller); a new onboarding step shows its progress, and Settings > Runtime has a matching "Local embeddings" section with status and Retry. Chat still needs a cloud provider key, added in Settings. An MCP server launched through `npx`/`npm`/`node` (such as Context7) also now works out of the box on Windows, via a bundled Node.js runtime.
- The Windows installer now shows the standard install wizard — a page to choose the install folder and a Finish page, with desktop and Start Menu shortcuts created — instead of a bare one-click progress bar.
- **The Linux release (`.deb` and AppImage) now bundles the same self-contained Python, local-embeddings Ollama runtime and Node.js as the Windows installer**, so neither a system Python, Ollama nor Node is required — the `.deb`'s own package dependencies no longer list Python at all. Everything else about the bundled runtime (the pinned packages, the first-run embedding pull, the Settings status sections, `npx`-launched MCP servers working out of the box) is the same as the Windows entry above.

### Changed

- **Specialist roles were reorganised.** *Developer* now both writes and runs code (it absorbed Terminal/DevOps and Distribution), so a task like "make a chart script and run it" is one job instead of a write step with no run step. New narrow specialists: *History Analyst*, *Data Processor*, *Document Creator* and *Configurator*; *Data Access* also owns external-API calls. The tool no specialist previously owned (`mcp_create_connection`) now has a home. Delegated turns are smaller (Researcher ~56%, Developer ~45% fewer prompt tokens). Existing sessions still display and replay correctly.
- The planner is told which roles are unavailable (e.g. no email account configured) and that a later step only sees earlier results, so earlier steps must return the actual values.
- Specialist roles are now defined in one manifest (labels, summaries, picker / plan flags, examples) instead of several parallel lists. No routing behaviour change.
- The message an agent gets when `python` is not found now points at Settings > Runtime instead of asking it to build a virtual environment itself.

### Fixed

- A very large, single-block tool result (e.g. raw JSON with no blank lines) could crash the local embedding server and then retry forever, flooding the log with the same crash. Oversized results are now split with a hard size cap, and a result that keeps failing is given up on after a few tries instead of looping (#171).
- A database query result over 200 rows was silently cut down while still reporting the real, uncapped row count as if nothing were missing. The complete result is now written to a workspace file instead of ever being truncated (#172).
- A question that needed both outside knowledge and your own data could skip the knowledge lookup entirely and go straight to the data, on both cloud and local models. It now reliably checks first (#173).
- A turn that ended on a bare warning — a misconfigured model, or clicking Stop — could leave the message box stuck as if still sending. It now resets correctly (#174).
- A tool call cut off mid-way by the reply length limit failed the whole step with "(no response)". It's now retried once with a nudge before giving up (#175).
- The assistant could accept an irrelevant search result as "domain knowledge found," and could query the same data twice instead of recognizing a matching column already in your database — producing a meaningless zigzag chart from unsorted data. Both are fixed: relevance is now judged, not assumed, and an existing matching column is recognized and reused (#176, #177).
- When the assistant found something but not enough to fully answer, it previously had no way to say so. It now reports "found something, not enough" and follows up once automatically (#178).
- A question that was pure domain knowledge could get both an MCP/wiki lookup and a web search scheduled before either had run. Web search now stays reactive instead of being scheduled in advance for this case (#179).
- Windows: the default workspace folder could land inside OneDrive sync instead of the plain Documents folder, when OneDrive has taken over the Windows Documents location — risky for the Python environment, database and model files it holds. The workspace now always resolves to the plain profile Documents folder on Windows (#202).
- Windows: after finishing first-run setup, the provider list and your sessions could stay empty until the app was fully restarted. They now appear immediately (#202).
- Asking what tools an MCP server has could send the assistant into a loop of up to 20 identical calls before giving a vague non-answer, because the tool only ever reported a count, never the real names. It now lists the actual tool names directly (#202).
- A follow-up question about an already-connected MCP server could make the assistant repeat the same lookup or connection-setup call dozens of times in a row (observed up to 26) instead of delegating to the right specialist. It now stops after two identical repeats with a clear message, or delegates correctly before that point (#202).
- Windows: an MCP server launched via `npx`/`npm` (such as Context7) failed to connect because the bundled Node runtime's own `node_modules` folder was being silently dropped from the installer. It's now included (#202).

## [0.2.2] - 2026-09-25

### Fixed

- A task that needed to run Python could fail with "Python is not available" even though the workspace already had a working virtual environment (`venv/`) with the packages installed: nothing told the agent about it, and a bare `python` doesn't exist on many systems. `shell_execute` now activates the workspace's `venv/` automatically whenever it exists, so `python` and `pip` resolve to it; and when Python is missing with no venv, the result says how to create one instead of leaving the agent to conclude it cannot run Python (#107).
- `write_file` could silently overwrite a real Word/Excel/PowerPoint/PDF/image file with plain text, corrupting it. It now refuses binary formats and names the right tool to use instead (#107).

## [0.2.1] - 2026-09-25

### Fixed

- A session could become permanently unusable after its first delegation to a specialist: every later message failed with the provider's own 400 ("messages with role 'tool' must be a response to a preceeding message with 'tool_calls'"). The specialist's own messages are saved between the delegate call and its result, so the saved history looked malformed when replayed to the provider. History is now repaired when it is prepared for sending — the specialist's nested messages are dropped from the replay (the delegate's result already carries their outcome), a genuinely unanswered call gets an explicit "no result recorded" error result, and any result that answers no call is removed. Nothing saved or shown in the chat transcript changes (#105).
- Corrects 0.2.0's fix for interrupted tool calls (#103), which repaired only genuinely unanswered calls and so did not cover delegated turns.

## [0.2.0] - 2026-09-25

### Added

- Rebranded from "Sachiv" to "Sachivji" everywhere user-facing, including the dev-mode Electron process/Dock identity (packaged builds were already correctly named).
- Real app icon (gear + person silhouette + capability badges), replacing the placeholder monogram.
- Widened providers: Google (Gemini) and Ollama (local, no key needed) adapters, behind a provider registry so adding one needs no renderer changes.
- Widened tools: `git_exec`/`git_clone_repo`, `github_cli`, MCP client (stdio + HTTP/SSE, live tool-registry merge), `search_history` (cross-session semantic recall), mechanical DB CRUD tools (`db_list_rows`/`db_count_rows`/`db_find_rows`) and agent-authored parametric saved queries (`db_save_query`), and a generic external-API access tool (`api_list_connections`/`api_introspect`/`api_call`/`api_check_status` — introspection via OpenAPI/Swagger, authenticated calls, automatic pagination, async job-status polling).
- Real per-provider token counting and cost estimation, a context/cost meter in the UI, sliding-window context retention, and tool-output trimming.
- Cancellation (Stop button, including mid-confirmation) and mid-run steering (edit a pending tool call before approving it).
- Multi-session concurrency — sessions can generate in the background independently; switching sessions or opening Settings no longer interrupts anything.
- A classify-and-plan pre-pass that detects a compound request up front and shows a live step checklist.
- Session auto-titling from the first message; PDF added alongside Markdown/JSON session export.
- Light/dark/system theme setting, tracking the OS preference live.
- Markdown and LaTeX math rendering for assistant messages, sanitized against untrusted content.
- Structured data-processing tools for HTML/CSV/JSON/XML, so an agent processes a large or raw document itself instead of pulling it into its own context.
- `web_search` now uses the Tavily Search API (Settings > Web search, keychain-stored key) as its primary path — a real search API with real ranked results and independently fetchable URLs, with `topic:"news"` support for current-events queries — falling back to DuckDuckGo's free Instant Answer API when no Tavily key is configured. (Both DuckDuckGo's and Google's actual search-results pages were confirmed empirically to be behind anti-automation walls unworkable for scraping; Google Custom Search JSON API was ruled out separately — as of a January 2026 policy change, new signups can no longer get full-web-search access.)
- Collapsible tool-call output: a global toggle (status-bar button, or Cmd+O on macOS / Ctrl+O elsewhere — the same convention as Claude Code) shows/hides the full body of each tool result, defaulting to collapsed (a compact ✓/✗ indicator per call) so the transcript doesn't look noisy by default; live agent status messages now include real round-progress (`round N/12`) instead of a bare "thinking"; the assistant reply bubble is noticeably wider (92% vs. 70% for user messages) to use the available space better.
- A default email account: with more than one account configured (Settings > Email accounts), one can be marked default, and `send_email`'s `connection` becomes optional — omitting it uses the default (or the sole configured account, when there's only one), and the confirmation dialog names the real resolved sending account before anything is sent.
- A generic/custom SMTP email provider (host/port/TLS given directly) in Settings > Email accounts, alongside Gmail, for any other mail server that supports password-based SMTP auth (Yahoo, iCloud, a company's own mail server, Zoho, and similar). A Microsoft-specific (Office 365/Outlook/Hotmail) app-password provider was evaluated and deliberately left out: Microsoft has fully retired SMTP Basic Auth — app passwords included — for both work/school and personal Microsoft accounts, confirmed against a real account, with no per-account way to turn it back on.
- Groq and Mistral provider adapters (OpenAI-compatible), plus rate-limit detection with wait-and-retry across every provider.
- MySQL as a database engine alongside Postgres and SQLite; the Postgres tools were live-verified against a real Pagila database.
- Inline image display in chat, and Mermaid diagram rendering in Markdown messages.
- `office_extract_template`: turn an existing document into a reusable template.
- Tool-output display limits and refined multi-call expand behavior; per-delegate round budgets, inline confirmation UI, workspace file organization by kind, and Excel formatting.

### Fixed

- A real launch-blocking bug in the first-ever packaged build: `sqlite-vec`'s native binary couldn't load from inside the asar archive.
- `electron-updater`'s ESM/CJS interop crash in a packaged build.
- `message_vectors` orphans left behind on session deletion.
- Three rounds of `search_history` relevance bugs (own-result reindexing, whole-message-granularity retrieval, no relevance floor on results).
- Reasoning models (gpt-oss, o1/o3-style) silently producing empty replies by starving on a flat 4096-token output cap — real per-model ceilings now apply.
- The local classify-and-plan call producing invalid JSON once a conversation already had a prior tool-use turn, by isolating it to the latest message only.
- Dock hover-tooltip showing "Electron" instead of "Sachivji" in dev mode (root cause: the `.app` bundle folder's own filename, not any Info.plist key) — and, in the same pass, reverted an earlier attempted fix for this that had silently broken `npm run dev`'s live renderer (an executable-file rename tripped Electron's own hardcoded `app.isPackaged` check, so dev launches silently served a stale prebuilt bundle instead of the live Vite dev server with no error anywhere).
- The context meter's window figure for a local model was wrong far more often than not: it was tied to sending a new message rather than the current provider/model choice (so simply opening an existing session kept showing a stale guess), and had no fallback for the common case of Ollama having idled the model out of VRAM between messages. Now refreshes proactively on load/model-change and falls back to the model's *configured* context (its Modelfile's own `num_ctx`) before the generic static guess.
- `parse_html` discarded every link on a page, so fetching a listing/topic page left the model with nothing but headline text — it would fabricate a plausible-looking article URL to follow up with, which predictably 404'd. Now also lists the page's real links. Also: the data-format tools' shared source resolution no longer rejects a call where a model filled in every schema field (`url` plus empty-string `filePath`/`text`) instead of omitting the ones it didn't use.
- `web_search`'s "Related" entries were presented as if they were fetchable sources — they're actually DuckDuckGo's own internal category pages, which sit behind the same anti-automation wall that rules out scraping DuckDuckGo's real search results at all (confirmed empirically). They're now labeled as informational-only, not something to fetch next; the tool also now surfaces the matched topic heading (DuckDuckGo's own disambiguation can confidently match the wrong sense of a query) and handles a grouped `RelatedTopics` shape it previously missed entirely.
- `search_history`'s startup backfill crashed on every single app start with a `FOREIGN KEY` constraint error, traced to a handful of orphaned messages left over from an unrelated development race — an unhandled insert now falls back gracefully instead of crashing the whole pass, and an orphaned message (however it got there) is skipped rather than retried and erroring on every future start.
- The "couldn't tell whether this request is simple or compound" warning was showing up in chat for the routine, harmless case (a local model not returning valid JSON for the classify probe) with no actionable next step — now only surfaced for the one case that's a genuine concern (the classification response was cut off by the output-token limit); the routine case still falls open safely, just without the chat noise.
- `parse_html` fabricating a URL still wasn't fully closed by only asking the model not to — found live again in a real user session, this time a fabricated *variant* of a real article's URL rather than a wholly invented one. Now enforced, not just advised: once real links are known for a site (from an earlier fetch), a follow-up URL that isn't the site root or an exact match to one of those real links is rejected outright, before any network call.
- A complex, multi-step request that hit the shared `MAX_TOTAL_ROUNDS` budget (12, shared across the top-level turn and every delegated specialist) silently discarded everything real that had already been gathered and returned a bare "Stopped after 12 agent rounds" stub — found live on a genuinely complex real request. Now makes one final, tools-disabled call asking the model to synthesize an actual answer from what's already in the conversation, falling back to the honest stub only if that wrap-up itself produces no text.
- A real request that made several `web_search` calls in one turn (refining a query that hadn't found what was needed yet) kept every one of those results fully expanded in what was sent to the provider on every later round of that same turn — nothing previously trimmed *within* a turn, only across turns. Now caps any repeatedly-called read-only tool to its most recent 3 results in what's sent to the provider; older ones collapse to a short marker. Only affects what's sent to the model — the full result stays in SQLite and the live/reloaded UI transcript either way.
- `db_create_connection`'s sqlite path could be a model-guessed workspace-relative path instead of the literal absolute path the user actually gave, failing with a cryptic "directory does not exist" error — an exact, existing path is still used as-is (sqlite connections aren't workspace-confined), but anything else now falls back to searching the workspace for a file with that basename before giving up.
- A chat turn could hang on "Thinking…" forever, with Stop no longer able to cancel anything, when a provider's stream ended without ever sending an explicit stop signal — seen live against Ollama/gpt-oss, whose chain-of-thought reasoning comes through a separate field this app never reads, occasionally ending the round with no visible content and no `finish_reason`. The stream now always synthesizes a clean end-of-turn signal itself when the underlying one never arrives.
- Math containing a bare `%` (an ordinary way to write a percentage) rendered as a visible KaTeX parse error instead of the number — `%` is LaTeX's comment character, so it silently swallowed the rest of the line including a closing `}`. Now escaped automatically before rendering.
- Clicking Stop while the classify-and-plan pre-pass was still in flight silently discarded the cancellation and fell through into starting a brand-new full round anyway, instead of ending the turn — now checked explicitly, so an abort during classification ends the turn immediately.
- A round that finished cleanly (not from hitting the output-token limit) but produced no text and no tool call ended the turn in total silence — nothing shown, nothing saved, indistinguishable from the app doing nothing. Now surfaces a warning explaining what happened, the same way an output-token-limit cutoff already does.
- A presentation-building request could get classified as a "coding" plan step, which has no deck-building tools at all, and silently fall back to a much plainer bullet-only slide tool instead of the real visual-design pipeline (`pptx_start_deck` + the isolated page-creator specialist) — found live on a real request. The classify-and-plan prompt no longer lists the delegate-only page-creator role as an apparent option, and now says explicitly that deck-building is never a plan step for any role.
- `office_create_document` rendered markdown syntax (`**bold**`, `- bullets`, numbered lists, pipe tables) as literal text in generated `.docx` files instead of real Word formatting, since a Paragraph was built from one un-parsed string — the model writes prose the way it would in chat regardless of the tool's plain-string schema. Bold/italic/code now render as real run formatting; a table or list written as markdown text (even inside a plain paragraph field) is now detected and converted into a real Word table/list automatically, and a dedicated `table`/`numbers` field is available for authoring them directly.
- The Data specialist could fetch large raw-row batches to manually total/compare by hand instead of writing one aggregate SQL query, and could substitute a similarly-shaped column for the one actually named in the question — found live on a request that fetched hundreds of rows across four separate calls, most unused, and still landed on the wrong number. Its guidance now requires planning the query up front (one SQL aggregate, not hand-summed rows) and matching a question's stated quantity to the column whose real name/semantics actually mean that.
- The Research specialist could treat a couple of broad, snippet-only search results as "done" research for a report/presentation-shaped request, leaving every downstream section thin and generic — found live. Its guidance now sets an explicit depth bar for that kind of request: search results are candidates, not the research itself, and the actual source content (via `parse_html`) needs to be read before the research counts as complete.
- A single unresponsive agent round (top-level or any delegate) could sit stuck indefinitely with Stop unable to cancel anything — found live, a real turn sat unresponsive for over an hour with confirmed-zero pending work anywhere in the process. Every round now has a timeout, and a whole turn now has a hard 15-minute wall-clock deadline; either one falls into synthesizing a real answer from whatever's already been gathered instead of hanging or discarding it all. A timed-out round's retry now also gets progressively more time than the attempt that wasn't enough, instead of repeating the identical timeout forever — a real design flaw in the original fix that could otherwise make a merely-slow (not hung) round on a slow local model literally unable to ever finish.
- A presentation the app reported as "created" could not actually exist anywhere in the workspace, with no error shown — an in-progress deck's state lived only in memory for the duration of one chat turn, so any turn that ended without an explicit save silently discarded the whole thing. The app now auto-saves any in-progress deck under a clearly-labeled fallback name if the turn ends before it was saved, with a message explaining what happened.
- A slide composed via the presentation-builder could end up with duplicated text/charts after a failed element was fixed and retried — the first, invalid attempt had already partially applied to the real slide with no way to undo it. Every element in a slide is now validated before any of them are applied, so a rejected call never leaves anything partial behind.
- An image element referencing a file that doesn't exist in the workspace used to fail only much later, at save time, with a bare "file not found" far from the actual mistake — now rejected immediately, by name, when the slide is composed.
- A tool call interrupted mid-flight (app quit or an abandoned stream) left an unanswered `tool_use` in the saved history, which made every later message in that session fail with the provider's own 400 — permanently. History is now repaired when it is prepared for sending, with an explicit "no result recorded" error result, so a session can no longer be wedged this way (#103).
- Whole-turn failures were silently resent as unanswered context on every later send; they are now collapsed into a single note (#102).
- The model treating a failed tool call (e.g. a missing required argument) as proof the capability didn't exist; the system prompt now tells it to read the error and retry with a corrected argument (#86).
- MCP stdio servers left running as orphaned processes after the app quit; every connection is now closed on quit (#86).
- Orchestrator hardening from an external code review: mid-turn context re-fitting, output-token budgeting that accounts for prompt overhead, MCP tools reaching delegated specialists, and Anthropic input-token accounting (#93–#100).
- A real turn-hanging bug in tool execution and a round-timeout gap for Ollama/OpenAI-compatible providers.

## [0.1.0] - 2026-09-08

### Added

- Electron + TypeScript + Svelte 5 desktop app scaffold, with `contextIsolation`/`sandbox` renderer hardening and typed IPC.
- Embedded SQLite persistence for sessions and messages; OS-keychain-backed credential store for API keys and data-connection secrets.
- Multi-provider chat (Anthropic, OpenAI, Google, Ollama) behind a unified provider adapter, with runtime provider/model switching.
- Multi-agent orchestrator (Planning, Research, Coding, Terminal/DevOps, Data, Distribution) with delegation-as-tool-call routing and live agent attribution in the UI.
- Tool suite with human-in-loop confirmation for mutating calls: file operations, shell execution, database access (schema introspection + generated SQL), AWS/Azure/GCP CLI tools, git operations, and the GitHub CLI (`gh`).
- MCP client (stdio and HTTP/SSE transports) with server configuration UI, merging discovered tools into the shared tool registry.
- Context/token-usage tracking with real-time cost estimation, a context meter in the UI, tool-output trimming, and sliding-window conversation retention.
- Cancellation (stop an in-flight response) and mid-run steering (edit a pending tool call before it executes).
- Session lifecycle: new session, delete (blocked for the active session), export to Markdown or JSON via native save dialog.
- Markdown rendering for assistant messages (headers, bold/italic, lists, code blocks), sanitized against untrusted model/tool output.
- Cross-platform CI (build, typecheck, test on macOS/Windows/Linux) via GitHub Actions.
