# Sachivji 0.3.2

**Status:** in testing (not published). A defects-and-small-improvements release on top of 0.3.1. Nothing needs to be done after installing: settings, chats and the workspace are kept.

Check list for testers: [`docs/manual_testing_0.3.2.md`](../manual_testing_0.3.2.md). Full technical change list: [`docs/CHANGELOG.md`](../CHANGELOG.md).

## New and improved

| What | In one line | Item |
|---|---|---|
| Agent menu | Click **Agent** in the status bar to pick Auto or a specialist from a menu (opens upward); Ctrl+Tab still cycles. | #193 |
| Confirm before delete | Deleting a chat asks first, and says it cannot be undone. | #230 |
| One window only | Starting Sachivji while it is already running shows a message and exits; the open window comes forward. | #131 |
| Auto-approve rules clearer | Each tool is tagged built-in, saved query or MCP server; stale rules can be removed; a Refresh button; plainer warnings. | #218 |
| Files stay out of the root | Shell commands that scatter four or more files in the workspace root now have them filed by type, like Python runs; Export Settings opens in `exports/`. | #204 |

## Fixed

| What | In one line | Item |
|---|---|---|
| Specialists introduce themselves | A pinned specialist now says which specialist it is, and what it can do, when you say "Hello" or ask "What can you do?". | #215 |
| No pointless MCP Operator | The MCP Operator is no longer offered while no MCP server is connected, so a "look it up in the wiki" request goes to the Researcher. | #146 |
| Long sessions keep file lists | When the context fills up, an old folder listing is shortened to its file names instead of being erased. | #170 |
| Empty planning replies explained | An empty planning reply now logs why (stop reason, token count); it is retried once, as before. | #140, #141 |

## For developers

- `vite-node` is pinned; `npm run eval:routing` and `npm run eval:cache` run the evaluation scripts (#134).
- Tests for the `aws`, `az` and `gcloud` tools, plus an opt-in live smoke test (#221).
- GPL-3.0-only licence (#231).

## Known limits

- A shell command that legitimately creates four or more files in the workspace root (for example unzipping an archive there) will have them moved; the reply names the new paths.
- Rules in Settings > Auto-approve rules are still per tool, not per MCP server or connection (planned, #227).
