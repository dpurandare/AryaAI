# Sachivji — Prerequisites for Windows 11 (AMD64)

What to install so the packaged Sachivji app (NSIS installer, `Sachivji Setup <version>.exe`) installs and runs with **all features** on Windows 11 x64. Sources: `README.md`, `electron-builder.yml`, and the tool code under `src/main/`.

The installer bundles Electron, Node, and every npm dependency. **You do not need Node.js or npm to run the installed app.** Those are only for building from source (section 5).

## 1. Required to start the app

| Item | Notes |
| --- | --- |
| Windows 11, 64-bit (AMD64) | Any current build. The installer is x64. |
| A modern GPU-capable display stack | Standard Electron/Chromium requirement; nothing to install. |
| ~500 MB free disk for the app | Plus the space in section 2 for the Python environment. |
| Network access to your chosen AI provider | At least one provider API key (OpenAI, Anthropic, Gemini, …) or a local Ollama (section 3). Keys are stored with Windows' own encryption (DPAPI via Electron `safeStorage`), so nothing extra is needed. |

The build is **not code-signed**. On first run, SmartScreen shows "Windows protected your PC": click **More info**, then **Run anyway**. Nothing is broken. In a managed enterprise environment, ask IT to allow-list the installer.

## 2. Required for full features: Python

Without Python the app still works, but agents cannot run scripts. That includes charts, Word/Excel generation by script, and data processing.

- **Python 3.10 or newer, 64-bit**, with `venv` and `ensurepip`. Python 3.10 to 3.13 work with the pinned packages; 3.14 does not (see section 6).
- Install from [python.org](https://www.python.org/downloads/windows/) with the **py launcher** option ticked. "Add python.exe to PATH" is optional. The app tries `py -3`, then `python`, then `python3`.
- **Do not rely on the Microsoft Store `python.exe` stub.** If it opens the Store, Python is not actually installed. Turn off the stub in *Settings > Apps > Advanced app settings > App execution aliases* if it gets in the way.
- Needs **~600 MB free** in the workspace drive. On first start the app creates `<workspace>\venv` and pip-installs a pinned set: `matplotlib 3.10.9`, `numpy 2.2.6`, `pillow 12.3.0`, `python-docx 1.2.0`, `openpyxl 3.1.5`.
- **Internet access to PyPI (`pypi.org`, `files.pythonhosted.org`) is needed once**, for that install. Behind a proxy or a restricted network, pre-create `<workspace>\venv` yourself and the app uses it as-is.
- Check the state in **Settings > Runtime**, which has Retry, Repair, and Turn Python off.

## 3. Recommended / optional components, by feature

Install only what you will use. The app tells you plainly when a tool's dependency is missing; it does not crash.

| Feature | Install | Notes |
| --- | --- | --- |
| Git tool (`git_exec`) | [Git for Windows](https://git-scm.com/download/win) | Must be on `PATH`. |
| GitHub tool (`github_cli`) | [GitHub CLI](https://cli.github.com/) (`winget install GitHub.cli`), then `gh auth login` | The app does not manage credentials. |
| AWS / Azure / Google Cloud tools | `aws`, `az`, `gcloud` CLIs on `PATH`, already signed in | The app does not manage cloud credentials. |
| Semantic search of past conversations (`search_history`) | [Ollama for Windows](https://ollama.com/download), then `ollama pull nomic-embed-text` | Ollama must be running. Alternatively point Settings > Search history at another embedding provider and model. Without either, that tool is disabled, with the reason shown in Settings. |
| Local chat models | Ollama, plus a model of your choice | Ollama loads models at a small context (often 4K) by default. See the README Troubleshooting section for the `num_ctx` Modelfile fix. A GPU with enough VRAM is strongly recommended. |
| Web search with real ranked results | A [Tavily](https://tavily.com) API key (Settings > Web search) | Without a key, the tool falls back to DuckDuckGo's Instant Answer API, which only covers well-known topics. |
| Stock images, `download_image`, `web_fetch` | Outbound HTTPS only | Stock images use the free Openverse API (`api.openverse.org`), with no key. |
| MCP servers (stdio) | Whatever the server needs. Most use **Node.js 22+ LTS** (`npx`), and some use **Python's `uv`/`uvx`** | Install only what the MCP servers you configure require. HTTP/SSE MCP servers need only network access. |
| Database connections | A reachable server: PostgreSQL, MySQL/MariaDB, or SQL Server | SQLite needs only a file path. Drivers are bundled; no ODBC driver is needed. |
| Email tool (Gmail) | A Gmail **app password** (needs 2-Step Verification on the account) | Outlook is not supported yet. |
| Office documents (Word/Excel/PowerPoint) | Nothing | Generated by bundled libraries and the Python environment. You only need Office, or a viewer, to open the files. |

## 4. Network / firewall allow-list (restricted environments)

Allow outbound HTTPS to whichever of these you use:

- AI providers: `api.openai.com`, `api.anthropic.com`, `generativelanguage.googleapis.com`, or your own endpoint.
- Python packages (first run): `pypi.org`, `files.pythonhosted.org`.
- Update check on launch: `api.github.com` and `github.com` (the Releases feed for `dpurandare/AryaAI`). Updates are not installed silently.
- Optional: `api.tavily.com`, `api.openverse.org`, `duckduckgo.com`, and `localhost:11434` (Ollama).

An admin can distribute provider and MCP settings to users with **Account menu > Import settings**. Secrets are never exported.

## 5. Only if you build or run from source (not needed for the installer)

- **Node.js 24 recommended, 22 also works, 20 does not.** CI and releases use 24; 22 was checked (typecheck clean, all tests pass). On Node 20 `better-sqlite3` segfaults as soon as a database is opened.
- **Git for Windows**.
- **Visual Studio Build Tools** (the "Desktop development with C++" workload) and Python 3, but only if `better-sqlite3` has no prebuilt binary and must compile. This is rare.
- Then: `npm install`, `npm run dev` (development) or `npm run dist:win` (builds the NSIS installer into `release\`).
- `npm install` downloads Electron (~150–200 MB) up front. Allow `github.com` release downloads and the npm registry.

## 6. Automated install (winget)

`scripts\install-prerequisites.cmd` installs and verifies the prerequisites above using winget, which is built into Windows 11. It checks what is already there first, only fixes what is missing or too old, and is safe to re-run.

```bat
scripts\install-prerequisites.cmd            :: Python only (the required part)
scripts\install-prerequisites.cmd -All       :: plus Git, GitHub CLI, Ollama + model, AWS/Azure/GCloud CLIs, Node 24 via nvm, uv
scripts\install-prerequisites.cmd -Git -Ollama
scripts\install-prerequisites.cmd -All -Yes  :: no confirmation prompts
```

Switches: `-Git`, `-GitHubCli`, `-Ollama`, `-CloudCli`, `-Node`, `-All`, `-Yes`.

What it checks and does:

- **Python:** accepts 3.10 to 3.13 that can import `venv` and `ensurepip`, and does not touch an existing one. Only if none is found (or only 3.14, or the Store stub) does it install 3.12. 3.10 is the app's own minimum; 3.14 is excluded because the pinned `numpy 2.2.6` has no 3.14 wheel (checked on PyPI). It also checks what `py -3` resolves to, because the app uses that command and it picks the **highest** installed Python. If that is not a 3.10-3.13 one, it offers to set `PY_PYTHON3`.
- **Platform:** Windows 11 only (build 22000 or newer) on x64 (AMD64) or ARM64. Windows 10, 32-bit Windows and other CPUs exit with an error. The CPU is detected from the OS itself, so it is right even inside an emulated or 32-bit PowerShell; a 32-bit PowerShell is re-launched as 64-bit.
- **ARM64 PCs:** installs the **x64** Python and the **x64** Node on purpose. `numpy 2.2.6` has no Windows ARM64 wheel, so the app's environment setup would fail with a native ARM64 Python.
- **Ollama:** installs it if missing; starts the server if it is installed but not running; pulls `nomic-embed-text` only if it is not already there; lists any chat models. It respects `OLLAMA_HOST`.
- **Node:** accepts any Node 24 or newer. Otherwise it installs **nvm-windows**, installs the latest Node 24.x, and runs `nvm use` so it becomes the default. It re-launches itself as administrator for this, because nvm-windows needs that to create its symlink. An existing standalone Node 18/20/22 is uninstalled first (after asking), because it would block nvm's symlink. Node managed by Volta or fnm is left alone. Global `npm -g` packages are not carried over. Node is only needed for `npx`-based MCP servers.
- **GitHub CLI:** reports whether you are signed in.
- **Pre-flight:** warns about Windows older than 11, under 3 GB free disk, and an unreachable `pypi.org` or `registry.ollama.ai`.

It does not sign you in to anything and does not set provider API keys. Open a new terminal afterwards so PATH updates apply.

## 7. Quick checklist (PowerShell)

```powershell
# Required for full features
py -3 --version                 # expect Python 3.10+; if missing, install from python.org

# Optional, depending on the features you use
git --version
gh --version
ollama --version
ollama list                     # should include nomic-embed-text for search_history
aws --version; az version; gcloud --version
```

If everything you need prints a version, launch Sachivji. Open **Settings > Runtime** to confirm Python is ready, then add a provider key under Settings.
